# RTX 3090 Ti Kingpin (GA102) on 617.42: survey, native status, V/F policies, fan selector

EVGA RTX 3090 Ti Kingpin, PCI `0x2203` / `0x49983842`, VBIOS `94.02.a0.00.a7`,
driver 617.42, on a custom water loop. All trials at idle, each restored and
verified. Raw results: [JSON](ampere-ga102-kingpin-61742-20261105.json).

Scope: one board on one driver. A W is request, readback and restoration, not
a physical effect.

## Read-only survey

Every registry-snapshot reader and every configured LPWR reader succeeded. The
policy layout is the large modern one (INFO 20512, CONTROL 13876, STATUS
397048 bytes). Notable results:

| Interface | Result |
| --- | --- |
| Clock offsets, per-domain clocks, V/F curve (127 points) | Read |
| NVVDD rail limits, offset, boost; voltage-request gate | Read; MSVDD unavailable |
| Six-word rail requests, incl. VCRIT low/high | Read (stored requests) |
| Clock V/F policy | Read: monotonicity and smoothing on |
| ELPG | LPWR controllers 0, 1, 4 and 5 present; 5 enabled |
| ELCG, BLCG, SLCG | Read, with BLCG and SLCG register witnesses |
| Individual GR and MS inhibits | Request support available |
| DIFR, media inhibits | Unavailable |
| Configured LPWR (GRPG, MS, media, NVDEC) | Read |
| Power-policy feedback bounds | Raw bounds read; Ampere rows not decoded (decoded since 1.9.1) |
| Power relationships | Weights read (all 1.0); target and source rows not decoded (decoded since 1.9.1) |
| Live VFE constants and bounds, offset scaffold | No supported rows |
| ELPG parallel capability (A801 type 12/attr 3) | Invalid flag, three stable reads |
| Idle thresholds, adaptive policy, PCIe speed | Druta implements these for GB20x only |

## Native board status (#59)

The board request binds to native policy 2, whose active upper feedback word
is 4424 (Q12). The relation the 5080 established by changing that word,

```text
native = floor((request_mW * upper_word + 2048) / 4096) mod 2^20
```

predicted every settled sample at all eight requests, including the wrap
between 970 and 971 W:

| Request | Native status |
| ---: | ---: |
| 850 W | 918,066 mW |
| 950 W | 1,026,074 mW |
| 970 W | 1,047,676 mW |
| 971 W | 180 mW |
| 1,000 W | 31,502 mW |
| 1,024 W | 57,424 mW |
| 1,500 W | 571,541 mW |
| 1,999 W | 61,924 mW |

NVML followed each request within about 0.47 s. The 3070 Ti's 33/32 factor is
consistent with an upper word of 4224 on that board, which was not read there.
Only policy 2 changed: every peer's default equals its maximum, so the 3070 Ti
peer model predicts no movement here and is not tested by this board.

## Clock V/F policies (#62)

Live monotonicity off and smoothing off were each accepted with exact readback
and restored. Druta's profile and Undo functions then verified, in order: an
Undo point taken before a live change restored it; profiles saved in changed
states (monotonicity off; both off) replayed those states; the baseline profile
restored both flags. The RTX 5080 refused the same live change in its default
startup mode; that refusal is unchanged.

## RmFan2XOverride (#71)

DWORD 1 is consumed. After a GPU restart the Fan2X GET returned RM `0x56`, NVML
fan speed read N/A, manual and automatic control were unavailable, and Druta saw
no fans. Temperature held at 22–23 °C. Restoring the absent value returned both
Fan2X entries, NVML control and both fans. The physical fan state could not be
observed on this water-cooled card.

## GRPG contracts (#51)

Read-only: `grpg_runtime.contracts()` refused every single-entry disable before
reaching any dependency projection. This ROM's LPWR index table (BIT P pointer
`0x74`) is version `0x10` with a 6-byte header and five **10-byte** rows; the
parser accepts only 18-byte rows. The GRPG table itself (version `0x10`, 10-byte
header, five 5-byte rows) matches. Supporting this board needs the 10-byte row
layout from an authoritative source. No registry change was attempted.

Since 1.9.1 the parser steps index rows by their declared size, and a GRPG
entry disable passed on this board: [GRPG trial](ampere-ga102-kingpin-grpg-61742-20261105.md).

## Combined-profile I2C (#61)

Not applicable on this board: the iCX controller is deliberately kept out of
saved and combined profiles (`profiles.capture`, `icx_mcu` branch), so a
combined profile carries no I2C component here. iCX settings use their own
explicit preset workflow.
