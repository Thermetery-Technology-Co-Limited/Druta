# NCT3933U current-offset control

Druta identifies this three-output current DAC by its two vendor-ID registers,
then provides independent output controls in nominal microamps. Enable
**I2C rail** to scan; nothing is scanned at launch. If several controllers
respond, select the intended controller by port and address.

Positive current means **source**, negative means **sink**. The chip does not
measure rail voltage. Board wiring determines whether a current increases or
decreases a rail, and by how much. Use a physical meter for voltage. The
documented current range is the DAC's representable range, not a voltage or
operating recommendation for the attached board.

**Read settings** refreshes the current commands. **Apply** changes only the
selected output; **Zero** clears it. **Zero all outputs** clears all three
current commands without changing configuration. Profiles and undo snapshots
save the exact output bytes and configuration; replay changes only output
bytes and requires the same controller route and unchanged configuration.

The default presentation is **Raw outputs (µA)**: OUT1, OUT2 and OUT3, their
signed command and raw byte. It makes no wiring claim. A user may select the
explicit **GPU / memory / PEX-PLL (mV)** mapping after verifying that board's
routing with a meter. That view labels each command as an *mV offset from the
register command*, never as live or absolute voltage; the signed raw current
and hexadecimal byte stay visible alongside it. The choice is local user
configuration keyed by adapter UUID, port and address. Without an adapter UUID
it lasts only for the current session. It is neither a shipped board allowlist
nor a hardware write.

The configuration's per-output doubling flags determine the current step:
10 microamps normally, 20 microamps when doubled. A non-representable request
is refused rather than rounded. When power saving disables outputs, Druta
reports that state and still distinguishes the stored command from an active
output. Druta never modifies these configuration flags.

## Interface and discovery

The public [Nuvoton NCT3933U datasheet, June 2013 Rev A2](https://mm.digikey.com/Volume0/opasdata/d220001/medias/docus/7434/NCT3933U.PDF)
documents:

| Register | Meaning |
|---|---|
| `0x5D`, `0x5E` | Read-only identification: `0x39`, `0x33` |
| `0x01`–`0x03` | OUT1–OUT3: bit 7 source/sink, bits 6:0 magnitude |
| `0x05` | Current doubling, power saving and reserved bits; read/preserve only |

CR04 is intentionally untouched: reading it clears a watchdog status flag.
Only the three documented output registers may be written. Each write uses
one byte and checks the complete output/configuration readback. An error
after dispatch attempts to restore the exact preceding output settings while
the original identity/configuration still match; otherwise Druta reports the
state as uncertain.

The six documented seven-bit strap addresses are `0x10`–`0x15`; datasheet
wire-address notation is `0x20`–`0x2A`. Detection probes the existing NVAPI
port range and requires the two ID bytes, without GPU model, board-ID or
driver-version allowlists. Finding this chip does not identify board wiring.

## Meter evidence for one ASUS CG611P / Strix-Poseidon route

Tests on 2026-09-23 used a TITAN Xp GPU transplanted onto a GTX 1080 Ti
Poseidon PCB, stock TITAN Xp BIOS and driver 582.66. Its NCT3933U responded
on NVAPI port 1 at seven-bit address `0x15`. These are observations of that
board, not universal bus routing or voltage conversions.

User-operated ASUS settings were correlated with separate register reads:

| Controller output | Meter-confirmed route | Normal `−10 µA` command | Doubled-command step |
|---|---|---|---|
| OUT3 | GPU | +10 mV | +20 mV |
| OUT1 | Memory | +10 mV | +20 mV |
| OUT2 | PEX / PLL | +66 mV | +132 mV |

For these three routes, negative current raises the measured rail and positive
current lowers it. The normal DAC command increment is 10 µA; CR05 doubling
makes it 20 µA. The normal mV increments were confirmed by the user on this
route; doubled increments are derived from the documented current doubling.
They are not a conversion for other NCT3933U boards.

All three outputs at `01/01/01` remained unchanged across 481 samples over
120 seconds, including 87.6 seconds of held P0. Configuration remained zero.

The production Druta backend then wrote `01/01/01 → 00/00/00`; all output
bytes and unchanged configuration were verified, with 16 further successful
snapshots. At the held P0 operating point, the user measured GPU voltage
falling from **1.128 V to 1.119 V**, a 9 mV drop. Meter work subsequently
confirmed the three routes and increments in the table above.

This local ASUS mapping may be preconfigured in that user's local settings.
The shipped UI remains raw OUT1/OUT2/OUT3 for every other board until its
owner explicitly selects and verifies a route.
