# Native I2C and Focused UI checkpoint — 2026-11-12

Reference: released 1.9.1 merge `fa6ee83`, its controller implementations and
`druta.icx.preset.v1` schema. This checkpoint ports the six controller families,
both MP2888A methods, and controller-specific controls/preset workflows. It is
not a claim of complete Python frontend parity.

Focused now has Rails and I2C pages. Gated sliders and actions are greyed out;
clicking them briefly highlights their enabling checkbox without changing a
draft or issuing a write. The explicit checkbox enables the corresponding
controls. Empty Apply tooltips are suppressed. Classic keeps its compact
split layout and integrated draggable V/F editor with WASD + Shift.

The Release build and bounded PE/import audit passed, along with all 27 CTest
suites. This includes 812 general UI checks and 229 Advanced-view checks,
headless catalog/mapping/checkbox interactions, protocol/recovery tests,
CUDA/hold lifecycle mocks and iCX preset integration tests. The latter verify
fresh capture before the file picker, staging without writes, selection binding,
skipping unchanged fields, complete final readback and partial-capture handling.

On the owner's RTX 3070 Ti, native discovery found the MP2888A at port 1,
address 0x20. Switching between offset and PMBus recipes and reading each was
successful without a write. Both explicit response-and-reversal Verify paths
then passed. The offset path exercised native CUDA warmup and temporary V/F
hold preparation; PMBus used the owned driver-enumerated 405 MHz clamp.
Both restored their captured controller requests before releasing their holds.
The offset returned to 0 mV; final PMBus read reported 675 mV and core 210 MHz.
The helper closed with no controller ownership, clamp or pending recovery.
These are controller-reported responses; no new multimeter measurement was made.

Surfaced current-request lines matched the read-only baseline afterward. The
final Classic capture still showed the user's configured 1917.26 W and
471.399 A current request. These values were not substituted with a previous
test's settings. Existing session tuning was not saved or automatically replayed.

All 11 read-only live window phases passed. Pause and normal minimization each
recorded zero frames and zero telemetry reads; Always refresh continued both
while minimized. Focused Rails, Focused I2C and Classic captures were reviewed.
The first smoke attempt used a missing output directory and produced no report;
the recorded successful run created the directory before launch. This is not
physical keyboard delivery, accessibility or legacy-OS qualification.

See [machine-readable evidence](2026-11-12-i2c-parity.json) for build hashes,
raw I2C outcomes and the window report. The other controller families have mock
protocol coverage but still need hardware qualification. Persistent discovery
hints, scan progress/cancellation and broader Classic parity remain tracked in
[the native UI plan](../../DESIGN-NATIVE-UI.md).
