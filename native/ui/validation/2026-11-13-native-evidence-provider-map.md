## Current boundary

`native/ui/voltage_limits_service.h:12` already defines raw equation packets, ROM-derived roles, independent rail policy, and retained-request comparison receipts. The optional `VoltageLimitsApi::equation_evidence` callback is at line 45. Its production provider is missing: the service must not infer REL/ALT/OV/VMIN from equation ordinals. The service captures native equation packets before calling the provider (`voltage_limits_service.cpp:67`), requires graph/image/policy/request evidence (`:98`), and checks retained requests after a selected write (`:147`). Existing raw capture is private to this service, not a reusable exported snapshot API.

`VoltageTablesApi` has raw rail readers and the qualified public request setter, but **no installed-scaffold evidence callback** (`native/ui/voltage_tables_service.h:35`). Its offset family remains explicitly unavailable (`voltage_tables_service.cpp:61`). An installed offset head is not an ordinary absolute voltage constant, even when both are constant equations.

## Delivery order and acceptance

1. **ROM getter and pure graph model.** Test alternate valid image/object layouts, EFI relocation and forbidden ownership, checksum/bounds, dangling/cyclic/shared graphs, aliases and unnamed clock dependencies. Export absence is unsupported; failed reads retain last-good as stale with bounded retry; identity/layout errors stop immediately. No driver-version or device-ID lists.
2. **Independent policy/request capture and equation provider.** Compose fresh target-bound captures, keep unknown bytes as comparison receipts only, and distinguish missing unrelated rails from a failed selected rail. Test current equation values differing from stored ROM while immutable graph still matches, independent partial families, transient failures, and mismatched slot/handle/architecture. Fill `VoltageEquationEvidence` only after those proofs. Stored ROM values and captured initial values remain distinct.
3. **Installed-scaffold recognition and typed selected writer integration.** Recognize already installed scaffolds from complete original/current evidence before enabling an offset. Test forged receipts, changed original roots/terms/variable/output, reused slots, unknown-byte drift, signed precision, stale receipts, selected-only writes and exact policy/request readback. Preserve meaningful typed Undo/recovery; never restore opaque packets.

Receipt size needs its own bound: a maximum captured ROM hex string is about 2 MB and the two 8192-row equation packets add about 3.94 MB before JSON overhead. The generic native manual-profile reader is capped at 1 MiB (`native/ui/profile_io.cpp:106`); simply calling it cannot load a complete scaffold receipt. Use a separately justified bounded, duplicate-key-rejecting receipt parser (for example 8 MiB after checking actual schema limits), without increasing ordinary profile limits. The Python scaffold loader itself does not supply a size bound.

Registry scaffold installation, driver refresh, and automatic startup/reset replay are not supplied by these providers. Inspecting an existing valid scaffold and explicitly applying a selected session request are separate operations. The unresolved ledger items remain REL/constants semantic evidence and installed-offset evidence until these production providers and their integration tests land; current switch-delay and six-word request controls do not close those items.
