## Composition restrictions to keep explicit

Native iCX presets work standalone, including fresh plan/typed Undo; the catalog deliberately refuses iCX mixed with other scopes (`core_client.cpp:1220`) because clock ownership/restoration is separate. Timing profiles work with compatible components but refuse simultaneous memory-offset changes (`:1222`) until the new operating band is established and a separate timing preflight succeeds. These are bounded composition limitations, not absent standalone implementations. Neither restriction closes the remaining full-composition goal.

For the next increments, first add native flag/gate and power-integral profile contracts plus per-fan capture, then attach already implemented standalone schemas to catalog preflight/execution/Undo. Each new catalog adapter needs: selected semantic targets and overlap checks; fresh whole preflight before first write; immutable loaded document; final selected readback after all components; partial-failure recovery receipts and meaningful grouped Undo. Tests must cover disjoint selections and coupled interference, not only successful round trips. Python combined validation/order/capture/restore are `combined_profiles.py:108`, `:207`, `:222`, `:310`.

Automatic startup/reset application and restoration of opaque firmware state are outside the authorized session-only manual profile objective. This audit does not propose porting Python startup replay. Describing a scope “unsupported” is only an honest refusal; every missing adapter or behavior above remains open until implemented and validated.
